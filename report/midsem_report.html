DyVo: Dynamic Vocabularies for Learned Sparse Retrieval with Entities

A from-scratch re-implementation of DyVo (Nguyen et al., EMNLP 2024), a CPU-scale reproduction of its headline comparison, and two extensions: one that makes DyVo robust to noisy entity candidates, and one that directly tests its “dynamic vocabulary” claim.

DistilBERT · monoT5 distillation · Wikipedia2Vec (2.59M entities) · 2,000 test queries · 8,067-paragraph index

How DyVo works

Learned sparse retrievers such as SPLADE weight the ~30k BERT word pieces, so an entity like Pachauri becomes pac ##ha ##uri. DyVo appends entity dimensions. A candidate generator (entity linker, retriever or LLM) proposes a few Wikipedia entities per text, and a head scores each one against a frozen external embedding:

w(e) = max_t log(1 + ReLU( α · ⟨h_t , P·E_e⟩ )) α₀ = 0.05, E_e frozen, P learned score(q, d) = ⟨ w_q , w_d ⟩ over [30,522 word pieces] ⊕ [entities] → still an inverted index

Because E_e lives outside the model, new entities can be added to the vocabulary without retraining. Extension B tests exactly this.

What we built

Model, matched to the authors' code

  • MLP query encoder and MLM (SPLADE) document encoder, as in the reference qmlp_dmlm_emlm config
  • DyVo head: scaled dot product, log1p∘relu, max-pool over tokens
  • KL distillation from monoT5; L1 on document word weights with quadratic warm-up; entities not regularised
  • 6 unit tests prove our speed-ups equal the reference maths

Everything we could not download

  • Entity linker over 2.59M Wikipedia2Vec titles (REL analogue): alias, surname and acronym tables, context-vector disambiguation. It links Tesla → Nikola Tesla and IPCC → Intergovernmental Panel on Climate Change
  • Dense entity retriever (LaQue analogue)
  • monoT5 teacher on CPU; paper-dataset converters for a GPU run

Where do entities help?

The aggregate hides two significant effects of opposite sign. DyVo helps when the query's entity is also a candidate of the relevant paragraph, and hurts badly when linking is inconsistent. The gate removes the damage.

Why our aggregate differs from the paper's. DyVo's gain is conditional on consistent candidates on both sides. REL (anchor-text priors plus neural disambiguation) is much more consistent than our title-alias linker, and long news documents almost always mention the query entity somewhere. The paper's own Table 2 makes the same point: candidate quality drives nDCG.

Extension A · DyVo-Gate: robustness to noisy candidates

The paper found that recall-oriented generators (BM25, LaQue) add noisy entities and do not improve nDCG. We gate each candidate with σ(MLP([retriever score, source flags, popularity, head evidence])), initialised almost open, and inject random distractor entities during training.

Extension B · Is the vocabulary really dynamic?

The paper argues that frozen external embeddings let DyVo use entities it never trained on, but it never isolates that claim. Test articles are unseen in training, so 420 test-query entities never appeared. We evaluate one trained model twice: with every Wikipedia entity, and with the unseen entities deleted from the index (a static vocabulary).

Supported. The gain appears exactly on entities added through external embeddings (+1.97 dynamic vs static, p = 0.0017), and a model with a trainable entity table instead of frozen external embeddings loses 1.54 on the same queries (p = 0.027). This is direct evidence for DyVo's central claim. Queries whose entities were all seen in training do not gain (78.33 vs 80.24): those are frequent entities such as countries, which separate paragraphs poorly.
